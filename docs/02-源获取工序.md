# 02 源获取：先搜，再拿，逐级降

## 源分级（永远按这个优先级）

1. **数字源**（MusicXML/MIDI 数字文件）：无识别误差，最高档
2. **印刷谱高清图**（1000px 以上、清晰）
3. **印刷谱普通图**（720p 级、有水印或轻遮挡）
4. **手写谱：不用**（手写 OMR 已被判定死路，最强 AI 也不做）

## 数字源直通线（用户持有数字文件时）

用户手上已有数字文件（自己打的谱、买的正版、下载的 MIDI／MusicXML），或愿意自己取——走这条**最快最准**的线：

1. **验证**：跑三件套（元数据核对 → 分布对拍 → 逐小节对齐），全过标"初验通过"
2. **转化**：MusicXML 直通下一步；MIDI 先转 MusicXML，转换后跑时值保真自检
3. **符号层**：数字源不含符号层；若同时有谱图则回填，没有就标注"无符号层"
4. **出谱**：进精排 → 成品；全程带来源与置信记录

数字源是用户自己的资源，本包只做验证与整合，不分发内容。

## 三层获取圈（从最自动到求人）

### 第一圈：免登录全自动（先全跑一遍）

| 平台 | 命令/方式 | 得到什么 | 边界 |
|---|---|---|---|
| 弹琴吧 | `opencli tan8 search "歌名 歌手"` | 版本清单（曲名/上传者/页数/链接） | 曲谱页"预览图"是专辑封面（非谱面）；高清谱在登录闸口 |
| B站 | `opencli bilibili search "歌名 钢琴谱"` | 谱源视频列表（含附谱/教学/还原） | 匿名最高 720p，1080 要登录 |
| IMSLP | `opencli imslp search` | 古典谱 PDF（全免） | 仅公有领域 |
| 通用网 | 采诗 web read、搜索引擎 | 各谱站/博客的谱页 | 视站点 |
| 小红书 / 知乎 / 抖音 | zhread 读链接（用户给的链接） | 用户分享的谱内容 | 搜索要登录；**用户给链接时可直接读** |

注意：bili-cli 的 search 偏"用户"结果；**搜视频谱源要用 `opencli bilibili search`**。

### 第二圈：自动拿（免登录能拿的）

- B站谱视频 → `yt-dlp` 下载 → `tools/bili_extract.py` 提页
- 可直接下载的图或文件 → 直接下载
- **拿到手必须进 04 验真，不许直接进流水线**

### 第三圈：才请用户（登录闸口，最后一招）

- 弹琴吧高清、Midishow（Cloudflare＋积分墙）、B站 1080 等
- 话术："这首的完整高清谱在站点的登录闸口里，您方便登录一下帮我拿下吗？约 30 秒。"
- 用户拒绝 → 退回上一档源，**如实说明清晰度降级**

## 版本择优

同一首搜到多版时：**数字源对上的 ＞ 印刷高清 ＞ 印刷普通**；平手时看与"原曲"的贴合（速度、编配、热度）。选定后记录：来源站、上传者、编号，写进谱库档案。

## 数字源验证三件套（拿到数字文件必跑）

1. **元数据核对**：音符数 / BPM / 时长，对着页面标称核（差得离谱先怀疑拿错文件）
2. **分布对拍**：与音频转录做音高类直方图余弦（0.95 以上约等于同一首）
3. **逐小节对齐**：按**文件自身 tempo** 把"拍"换算成秒（坑：music21 的 offset 单位是拍不是秒，Basic Pitch 输出的文件 tempo 是 120 默认值），逐小节音高类 Jaccard 加**偏移扫描**找最优对齐（零偏移最优＝天然对齐）

三件套全过，才许标"初验通过"。
