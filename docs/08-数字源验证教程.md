# 08 数字源验证教程（verify 三件套）· 2026-10-13

手上有数字文件（自打／正版／下载）时，别直接进链：先过三件套。三件全过才标「初验通过」；未跑的件如实留缺，不静默降级。

依赖：music21、numpy（核心档）。命令在仓库根目录运行。

## 第一件 元数据核对

    python3 tools/verify.py metadata 文件.mid

预期输出四行：音符元素数（和弦算 1）／展开音数（和弦展开）／文件 tempo／时长（按文件 tempo 折算）。

带标称值时加参，命令把差直接打出来：

    python3 tools/verify.py metadata 文件.mid --notes 1200 --bpm 72 --dur 180

判定：差为 0 或极小即过。差大先查口径：展开音数与发声数是两种口径（见 docs/06），先写清用的是哪种再谈差。

## 第二件 分布对拍

    python3 tools/verify.py dist 文件A.mid 文件B.mid

预期输出：两张 12 列音高类直方图＋余弦相似度。0.95 以上约等于同一首。

判定：同曲两个来源（自打与下载、切片与整曲）对拍过 0.95 即互为佐证；低于 0.9 先怀疑不是同一版本，或转谱有错。

## 第三件 逐小节对齐

    python3 tools/verify.py align 数字源文件 对照转录文件 --bars 56 --bpm 68

预期输出：两文件小节数、offset 扫描（−8 至 +8）逐行一致度表（最优行带标记）、最优 offset 与平均一致度、一致度不低于 0.6 的小节数。

判定：最优 offset 处一致度要明显高出邻位，才算对齐可信。Jaccard 受对照源自身精度封顶，是下界指标，别当准确率用（见 docs/06 纪律三条）。

## 坑（最容易踩的三个）

1. music21 的 offset 单位是拍不是秒；跨文件对比按各文件自身 tempo 换算。
2. 无 tempo 标记的文件按 120 BPM 处理（音频转 MIDI 的输出常如此）。align 对照侧默认按 68 BPM、4/4 折算，曲子速度不同必须改 --bpm。
3. 先约定口径再比数：数字对不上时，先核对是不是同一个口径。

## 自查

不确定自己这份能跑哪几件：

    python3 tools/verify.py checklist 文件.mid --other 第二来源.mid

输出「哪几件能跑、还缺什么」。单文件输入时后两件如实留缺。
