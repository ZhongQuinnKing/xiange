统一评价体系 v1.0（2026-10-10 立）

立此文档的原因：在这之前，评测口径有四套，各算各的账。

一、乱源盘点（立标准前实况）

四个脚本，四种说法：
1. double_read_compare.py——双读比对，判据三层：完全一致（音名序列与时值序列全同）、音高一致（音高类集合同、时值有差）、不一致。按小节、分左右手计数。
2. verify_vs_audio.py——机器与谱面比对，算每小节音高类集合的 Jaccard 相似度，自标为下界估计（音频含伴奏残留）。
3. melody_v4.py——简谱音级转录（1=G、前缀升降、后缀八度），是简谱侧的"真值"格式。
4. score_doctor.py——只做体检（声部、音域、跨度过大），不打分。
另有三色账（绿/黄/红）散在核账会话里，手算。

后果有三：
1. 口径不统一，数字不能比——93.9% 与 0.988 是两个尺度上的数
2. 共识率被误读为准确率——共识高不等于对（两个引擎可能同错）
3. 下界估计容易被当成错误率——Jaccard 本来自标下限，报数时常被丢进"准确率"一栏

二、四级度量定义

比对的单位是"音符事件"：谱面里一个发声的音，含音高（含八度）、时值、所在小节、所属声部。

第一级 音高级（单音）
命中判据：音高七成上同音名，八度差也算不中。全轨"音高命中率"＝命中数÷真值总数。
口径提示：八度差单开一栏统计，因为它是最常见的系统错，混进命中率里会掩盖问题。

第二级 时值级
在音高全同的事件上比时值。容差=一个标准量化单位（十六分音符，0.25 拍）。超容差记为时值错。
口径提示：时值错分两类——总长错（小节对不上拍）与切分错（总长对、位置偏）。分开计。

第三级 结构级
小节数、小节线位置、拍号、调号。独立抽查，不混进音符账。

第四级 符号级
连音线、断奏、力度、踏板、反复记号。
口径提示：OMR 引擎普遍不认这些，精度低但被承认度低。独立栏报，好坏都是它自己。

三、报告卡（标准输出）

每次核账产出统一报告卡，固定格式：

  曲名与版本
  真值总量：X 个音符事件、Y 个小节
  音高级：a/b = c%（八度差 n 处单列）
  时值级：在音高命中的 a 个事件上，时值全同 m、总长错 p、切分错 q
  结构级：小节数一致否、拍号一致否
  符号级：（若真值有标注）命中率
  三色账：绿＝音高时值全同；黄＝音高对时值差；红＝音高错
  口径标注：本卡为真值全额核对 / 抽样核对 / 下界估计（注明来源）

  报告卡末行固定写：核对日期与核对人（人判还是机判）

三点五、容差规则（2026-10-10 自校验定，实测踩坑后立）

时值判定容差＝min(0.26, max(0.04, 0.15×事件时长))。
立这条的原因：最初的实现用固定容差 0.26，自校验场景四（时值整体减半）漏判——0.5 拍与 0.25 拍之差恰好 0.25、落在 0.26 内，系统性时值错被判成"全同"。凡时值量级与标准谱不同的数据（缩拍数据、极快段），固定容差都会系统漏判。相对容差（15%）在两个量级上都正确：0.25↔0.25 判同（差 0），0.5↔0.25 判不同（差 25%）。
五场景自校验（selftest.py，可复跑）：自比全绿／低八度被标／大三度平移大量红／时值减半全黄不红／删音被标漏——五条全过才算判据正确。


三点六、域内/泛化分栏（2026-10-10 夜立，古琴泛化轮教训）

背景：古琴域内 98% → 换曲 3.3-15.7%（崩在分类层字体域外）——单域成绩不可外推。

规则：**任何成绩必须标明"域内"还是"泛化"**——
- 域内＝被测样本与开发/调参同域（同曲同字体同版式）
- 泛化＝跨域样本（异曲/异字体/异版式/异质量）
- 报告卡成绩栏默认两栏并列；只报域内＝不可采信于对外承诺
- 与"两把尺分开报"同族：都是防口径混用。

四、三条使用纪律

1. 任何数字出库必须带口径标注——不写口径的数字不许上报、不许进对比表。
2. 共识度与准确率分开报——共识是引擎间一致性，与真值核对才是准确率。两者都报时分别标名。
3. 下界估计只写下界，不许当错误率用（Jaccard 类指标尤其）。

五、与技能包的对接

这四级就是技能包"错误可见"原则的实体：绿黄红三色账是用户看得见的账，四级度量是它的计算底座。
用户侧只给三色账与命中率，内部侧保留四级全账与 [待裁] 标记。
出库闸联动：报"已验证"必须附标准报告卡（见记忆 score-error-gates）。

附：格式对照（现有四格式与统一模型的转换口径）

1. jp/pages/*.md（双读格式）：小节号 + RH/LH + [音名序列]:时值；R=休止
2. melody_v4 简谱格式：1-7 音级（1=G）、b/#前缀、+/-八度后缀、0=休止；时值以四分音符=1.0
3. MusicXML/MIDI（引擎输出）：music21 直读，取音符事件
4. 数字源（MIDI 真值）：music21 直读；注意按文件自身 tempo 换算时间（已知坑）

三点七、渲染口径（2026-10-10 夜立，大考小样实测）

同 PDF 同引擎，渲染分辨率不同则成绩差近一倍（实测 30.6% vs 16.1%）。
规则：任何走"PDF→图→识别"的成绩，**渲染参数（分辨率/DPI/转换工具）必须写进记录**；跨成绩对比前先对齐渲染口径。
